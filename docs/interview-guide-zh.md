# 面试准备指南（中文）

> 定位：这是 Herui 的独立求职作品，全部 synthetic 数据；不是任何实习/雇主系统，不能说成雇主业绩或生产准确率。
> 代码由 AI 辅助编写——面试前**必须自己能讲清下面每条规则、能在代码里指出位置**，这是本文件的目的。

## 1. 一句话介绍
「一个本地的支付对账工作台：把内部账本、PSP 结算明细、银行流水三份 CSV 导入，分两条链核对（账本毛额 vs PSP 交易毛额；PSP 结算净额 vs 银行入账），只在证据唯一且充分时自动匹配，其余变成带证据、可审计的异常案例，并出日终报告。」

## 2. 关键规则取舍（为什么这样设计）
| 取舍 | 选择 | 理由 / 代价 |
|---|---|---|
| 金额表示 | 整数「分」，Decimal 解析，0 容差 | float 会产生 0.1+0.2 问题；容差会把真实差异（比如缺 0.01）悄悄抹平。代价：上游格式必须干净。 |
| 两条链分开 | A 比 gross，B 比 net | 银行收到的是扣费后的净额，拿它对账本毛额必然对不上，也会把费用误判为差异。中间用 gross − fee = net 的桥接表连接。 |
| 自动匹配门槛 | 引用证据优先；无引用时金额+日期必须**双向唯一**；纯金额凑组合只给建议 | 宁可多一点人工复核，也不要错配（错配比漏配更危险：会把真实缺款隐藏掉）。adversarial holdout 里 0 误配、B 链覆盖 47%——这就是代价。 |
| 反贪心 | 先建完整候选表再决策 | 贪心会先吃掉某条记录，导致后面的歧义被隐藏（D-04 就是这个类型的 bug）。 |
| 业务键作用域 | (merchant, business_ref)；记录 ID 按来源全局唯一；标识符禁止 `| , ; /` 空格 | 不同商户可能重用订单号；分隔符碰撞（D-09）会导致身份混淆。 |
| 冲突数据 | 隔离 + 阻止匹配 + 开 SOURCE_CONFLICT 案例 | 同一键两个版本时，系统不该替人选「哪个是对的」。 |
| 人工处理 | 只记录决策，不生成 matched，不改金额 | 否则报表会显示「已对平」而钱其实没到。 |
| 历史 as-of | 往回看的 run 是只读快照（D-08） | 回看过去不能关掉今天的案例。 |
| 审计 | SQLite 触发器禁止 UPDATE/DELETE | 只是 app 层控制；有数据库文件的人仍可改——不能称为防篡改或合规。 |

## 4. 20 个可能的追问（附要点）
1. **为什么不用模糊匹配/容差？** 金额错一分也是真实差异；日期才给容差（A 链 ±2 天，B 链 −1/+3 天）。
2. **A1 匹配需要哪些条件？** 同商户+同引用+同币种+同类型+金额完全相等+日期差≤2。
3. **银行拆分入账怎么处理？** 多条银行流水引用同一批次，合计等于净额且都在窗口内 → B2S；少了就是 PARTIAL_RECEIPT。
4. **合并入账？** 一条流水引用多个批次号，批次净额合计等于流水 → B2M。
5. **没有引用时怎么办？** 同账户同币种、金额相等、窗口内，且双向唯一才 B3；否则 AMBIGUOUS。
6. **为什么纯金额组合不自动匹配？** 子集和随数据量组合爆炸，巧合概率高；只作为建议。
7. **怎么保证一条记录不被用两次？** 引擎断言 + 数据库唯一约束 + 测试。
8. **输入行顺序会影响结果吗？** 不会：排序+先建完整候选；测试做了 25 次打乱。冲突行「谁先落库」取决于顺序，但结果都是阻止匹配，所以状态不变。
9. **同一个文件导两次？改名再导？** 按内容 SHA-256 判重，改名无效；内容不同但行重叠则逐行判重。
10. **3 行里第 3 行坏了？** 默认 PARTIAL：2 行入库 1 行隔离，控制合计只算入库行；strict 模式整批回滚。
11. **退款跨日？** 退款是负数事件，有自己的引用；日期容差内就匹配。
12. **费用在哪体现？** PSP 行 net = gross − fee 强校验；单独费用行只进 B 链净额；报告有 gross/fee/net 桥接。
13. **未结算/在途怎么区分？** NOT_DUE（可结算日+2 天内）、IN_TRANSIT（结算日+3 天内）不算异常，过期才开案例。
14. **迟到数据来了怎么办？** 重跑后匹配上的案例由 system 自动 AUTO_CLEARED，写明规则和组号，note 保留。
15. **如果有人手工标 Resolved 但钱没到？** 案例保持 Resolved，但标记「still unmatched」，报表单独列出。
16. **as-of 往回选会怎样？** 只读快照，不改案例，UI 有提示。
17. **历史报表会不会混入今天的数据？** 不会：每次 run 存导入水位线和异常快照（D-10 修复）。
18. **benchmark 分母怎么定义？误配怎么算？** A：两边都存在的真值对；B：真值支付组，只有完全相等才算对，部分重叠算误配。
19. **这些数字能说明生产准确率吗？** 不能。生成器和规则是同一作者写的，数据分布是假设的；它只证明机制和取舍。
20. **下一步会做什么？** 外部用户 UAT、多用户权限+maker/checker、FX、真实格式（如 CAMT.053）解析、引用拼写容错（需要证据评分）。

## 5. 必须本人真正理解、不能背答案的点
- 为什么 B 链不能拿 ledger gross 对 bank；手算一次 golden S01：1000 − 20 = 980。
- 手算一次 S04 拆分：3000 + 2000 = 5000；S05 合并：970 + 485 = 1455。
- D-04 的具体例子（90 = 90，也 = 40 + 50）以及为什么要转人工。
- 三种「没匹配但不是异常」的状态（PENDING / NOT_DUE / IN_TRANSIT）和各自的宽限期。
- 案例生命周期表（`docs/matching-rules.md` 末尾）。
- 这个项目**不是**什么：不是生产系统、没有身份验证、不是合规审计、没有外部用户验收。
